{/*
  CASE STUDY TEMPLATE — copy this file, don't edit it in place.

  This captures the exact pattern used for the BetterUp case study
  (src/content/case-studies/betterup.mdx), finalized after several rounds
  of visual QA. Use it as the starting skeleton for every other case study
  (Airbnb, Rutter, Flyr Labs, Hinge Health, TruStage) so they all read as
  one consistent system.

  HOW TO USE THIS FILE
  1. Copy it into src/content/case-studies/<slug>.mdx (this file itself
     lives in docs/, NOT in src/content/case-studies/, specifically so it
     is never picked up as a real route — getAllCaseStudySlugs() in
     src/lib/case-studies.ts only scans that one folder).
  2. Fill in the frontmatter and every placeholder in ALL CAPS below.
  3. Get each image's real pixel width/height (e.g. via PIL:
     `Image.open(f).size`) and use the exact numbers for imageWidth /
     imageHeight on <MediaSplit> — it renders uncropped at that ratio, so
     wrong numbers will visibly stretch or squash the image.
  4. Delete any section you don't need (not every case study needs 2
     MediaSplit sections, a carousel, AND a quote pair) — this is a
     skeleton, not a required checklist.
  5. Run `npm run build` and `npm run lint`, then screenshot the page
     (see "Verifying changes" below) before calling it done.

  THE MARGIN SYSTEM (the thing most likely to look "off" if skipped)
  Every text element on the page — the big title, the category/dates row,
  each section's eyebrow/headline, and the quote band — uses an
  asymmetric left inset on desktop/tablet only (mobile stays at the
  standard px-6 on both sides):
    - Text's outer margin:  sm:pl-[60px]  (60px instead of the standard 40)
    - Image's outer margin: sm:pl-10 / sm:pr-10  (standard 40px, unchanged)
  <MediaSplit> handles this automatically via its `side` prop — it flips
  which edge gets the 60px vs the 40px depending on which side the image
  is on. The page title (in src/app/(site)/[slug]/page.tsx) and <Meta>
  hard-code sm:pl-[60px] directly since they don't have an image
  counterpart. If you add any new full-width text block outside
  <MediaSplit>, give it sm:pl-[60px] sm:pr-10 (mobile: px-6) to match.

  IMAGE PNG→WEBP CONVERSION GOTCHA (bit us once already)
  If you convert a PNG to WebP with a transparent background, do NOT call
  `.convert('RGB')` in PIL before saving — that silently drops the alpha
  channel and transparent pixels render solid BLACK instead of see-through.
  Keep the image in RGBA mode and save straight to WEBP; PIL preserves
  transparency natively. Only flatten to RGB for images you've confirmed
  have no transparency (fully opaque photos/screenshots).

  VERIFYING CHANGES
  Real pipeline used throughout this project: `npm run build` + `npm run
  lint`, then start the server (`npm run start`) and screenshot with
  Playwright using the lock-screen cookie
  (tg_site_access=tg-portfolio-2026-granted) — scroll through the page in
  ~800px increments before capturing, since next/image lazy-loads and a
  single full-page screenshot can miss below-the-fold images.
*/}
